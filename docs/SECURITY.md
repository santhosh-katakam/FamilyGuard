# Security and privacy boundaries

One administrator is bootstrapped from environment configuration into admin_users.id=1; passwords use BCrypt cost 12. The password environment variable is used only on first creation, not to overwrite credentials on each restart. Account deletion disables the singleton row, revokes sessions, deletes pairing/device/event data and prevents automatic re-creation on restart. The disabled singleton row is a tombstone: email and password hash are replaced with non-identifying random/placeholder values and privacy settings are reset. A separate operator-managed reset is needed to create a new family.

JWT access tokens expire after 15 minutes; seven-day refresh tokens are random, stored hashed, sent only in HttpOnly cookies, and rotated on each refresh. New login advances the session version. Cookie auth requires an exact trusted Origin to avoid CSRF. Parent tokens and device credentials are isolated by endpoints and database lookups. One random 256-bit device token is issued once at pairing; only its SHA-256 hash is stored on the server. Revoke removes the device and its credential. Short-lived 12-character random pairing codes are stored hashed, consumed once under a parent-row database lock, and expire in five minutes. Pairing and login are rate-limited to 12 requests per minute per endpoint/IP; other traffic is limited to 240 requests per minute per credential/IP in one JVM. Deploy behind trusted ingress; forwarded-client IPs are not used for rate-limit keys. Distributed/multi-instance deployments require shared rate limiting and WebSocket fanout.

All event payloads (including coordinates) and privacy/geofence settings are AES-256-GCM encrypted at rest with random IVs. Query fields (package name, category, event timestamps, device ID), alert text, device name and permission names are metadata and are **not** field-encrypted. Provider volume encryption, network restrictions and DB access controls are still required. No claim that the entire database or all metadata is application-encrypted is made. Local Android payloads and tokens are AES-GCM encrypted with a non-exportable Android Keystore key; Room indexes/category/time remain metadata. Application backup is disabled. A wiped or invalidated Keystore requires re-pairing and clearing unreadable local data.

The server validates and allowlists payload fields; notification contents and extra fields are discarded. No phone numbers, notification bodies, contact lists, call recordings or credentials are collected. Notification package controls live on the child. Global sharing switches live on both ends: the parent can reduce collection, but cannot override local consent or Android permissions. Permission events and battery/monitoring status continue as minimum connection metadata while monitoring is paused, until the child removes the local pairing. Pausing discards pending events and sends a visible-disabled report when connectivity permits. Explicit local unpair removes the credential and queue; the parent must revoke the server record to pair again.

The child has no remote command execution, covert mode, uninstall prevention, permissions bypass, Accessibility scraping or device administration. Notification service access cannot guarantee incoming messages or chat history. Call-state observation excludes VoIP and audio. Recording is unsupported. A separate consent-based recording workflow would need the device's explicit supported dialer/manual recording capability, visible consent, local review and a separate design; no recorder or audio uploader is bundled.

WebSocket handshakes require short-lived one-use random tickets from an authenticated parent API. They transmit only refresh invalidations, never activity payloads. Web connections validate session version; native connections validate the separately enrolled receiver credential on each signal and during periodic revocation checks. Receiver registration verifies the existing Parent Admin password and enforces a singleton phone; replacement explicitly revokes the previous credential. The server stores a token hash with a 30-day expiration; Android stores the token using Keystore encryption. The receiver has only feed/ticket/acknowledgment permissions and cannot upload child events or perform parent administration. It does not invalidate web sessions. Tickets cannot survive restart. Do not log URL query strings at the proxy because tickets appear there for WebSocket compatibility.

Parent delivery records are an allowlisted metadata outbox, not a copy of notification bodies. Current sharing preferences are rechecked on fetch; sequence acknowledgments are bound to the currently registered receiver and cannot advance beyond an offered page. Pending events have a seven-day/20,000-row limit, reduced by shorter retention settings. Parent Room receipts are encrypted and capped at seven days/2,000 records. Quiet/category suppression acknowledges without an OS alert. Phone replacement starts from enrollment time, and unpairing/account deletion erase the relevant pending records. The user-started receiver uses a persistent visible foreground notification and stops when its visibility is disabled; no FCM, SMS access, hidden boot restart, wakeup bypass or new third-party notification service is introduced.

Before real deployment perform dependency/security review, real PostgreSQL validation, hardware permission testing, backup restoration testing, and an appropriate privacy/consent review for your household and distribution channel. Broad package access and sensitive permissions are not automatically eligible for app-store distribution; review store policies if distributing. This repository is an implemented baseline, not a certification of production safety or legal compliance.
